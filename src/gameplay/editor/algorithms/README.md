# 关卡编辑器算法扩展

编辑器算法采用独立策略模块。算法可以拥有完全不同的参数结构和路径逻辑，不要求与算法1共享数值字段。

## 数据结构

对外关卡 JSON 每个关卡只包含 `data` 二维数组：

```json
{
  "data": [
    [1, 2, 3],
    [6, -5, 4],
    [7, 8, 9]
  ]
}
```

正整数表示显示数字；负整数保留原数字的绝对值并表示隐藏，例如 `-5` 表示隐藏数字 5；`0` 表示该位置不属于关卡。数字绝对值必须从 1 开始连续且不重复。导出多个关卡时，文件根节点是上述对象组成的数组。

算法选择和参数只用于编辑器运行时生成路径，不写入对外关卡 JSON。读取 JSON 后按二维数组还原完整路径和隐藏格。

新建编辑器关卡默认使用算法4：最大交叉数量 `20`、拐弯概率 `40%`、隐藏比例 `50%`。

六边形蜂窝棋盘不产生交叉，所有算法都会将 `targetCrossings` 解析为 `0`。编辑器中统一按“最大交叉数量”解释，不会为了凑满该数值主动制造交叉。

算法2会从全部激活格中按生成种子随机选择起点，不再偏向边缘或内部；若棋盘拓扑本身存在两个强制端点，则仍从合法端点开始。大多数步骤按“拐弯概率”随机打乱候选方向，少量步骤使用低自由度安全引导，死局、断路或超过交叉上限时通过回溯改走其他方向。每次生成多条完整路径后随机选择一条；若随机搜索未在预算内完成，则使用稳定搜索作为后备。随后随机翻转仍能合法重连的路径片段，每次变换都重新验证相邻关系和交叉上限，用来打散局部区域的填充顺序。确定路径后按隐藏比例、最长连续隐藏和最长连续显示生成固定隐藏数字，不再搜索第二解或修复显示数字，因此同一组显示数字可以对应多条完整的一笔连解。

算法3复用算法2的完整路径生成，只替换隐藏候选的选取方式。每个非首尾数字会先分类为直线、拐弯或交叉；交叉指参与几何交叉的两条线段两端数字，并优先于另外两类。三类概率分别决定格子能否进入本次隐藏候选，隐藏占比限制总数量，隐藏成片最大尺寸限制空间上相邻的隐藏格连通块大小，与数字是否连续无关。方形、菱形和长方形按八邻域计算成片范围，六边形蜂窝按六邻域计算。概率、占比或成片尺寸无法同时满足时，实际隐藏数量可能低于目标值。算法3同样不搜索第二解、不强制唯一解。六边形蜂窝棋盘没有交叉，交叉相关参数在编辑器中禁用。

算法4复用算法2的完整路径生成，但拥有独立的隐藏选择逻辑。它先将目标隐藏数的约一半作为空间上互不相邻的种子，再优先让每个种子向周围邻格扩张，其余数量继续从已有隐藏区域的邻接边界生成。每次加入隐藏候选前，都会重新统计当前各显示数字周围的隐藏数量，优先选择能够覆盖最低计数显示数字、且不会同时继续抬高高计数区域的候选；同等候选才按生成种子随机选择。若已有区域受最长连续隐藏限制而无法继续扩张，才补充新的独立种子。生成完成后会修补超过最长连续显示限制的区段；隐藏比例是目标值，为满足连续显示限制，实际隐藏数量可能略高于目标。方形、菱形和长方形按八邻域判断相邻，六边形蜂窝按六邻域判断。

## 新增算法

1. 在 `types.ts` 定义独立参数接口和 selection，并加入 `EditorAlgorithmSelection` 联合类型。
2. 新建算法模块，实现默认参数和执行逻辑。
3. 在 `registry.ts` 注册名称、说明、兼容解析和运行分派。
4. 在 `parameterEditors.ts` 添加该算法专属的 DOM 参数面板。
5. 算法运行只接收 `EditorAlgorithmContext`，不要直接访问控制器、视图或 localStorage。

算法模块负责规则，参数编辑器负责 DOM，`LevelEditorModel` 只保存选择并调用注册表。
