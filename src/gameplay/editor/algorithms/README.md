# 关卡编辑器算法扩展

编辑器算法采用独立策略模块。算法可以拥有完全不同的参数结构和路径逻辑，不要求与算法1共享数值字段。

## 数据结构

对外关卡 JSON 每个关卡只包含 `data` 二维数组：

```json
{
  "data": [
    [1, 2, 3],
    [6, -5, 4],
    [7, 8, 9]
  ]
}
```

正整数表示显示数字；负整数保留原数字的绝对值并表示隐藏，例如 `-5` 表示隐藏数字 5；`0` 表示该位置不属于关卡。数字绝对值必须从 1 开始连续且不重复。导出多个关卡时，文件根节点是上述对象组成的数组。

算法选择和参数只用于编辑器运行时生成路径，不写入对外关卡 JSON。读取 JSON 后按二维数组还原完整路径和隐藏格。

编辑器的“识别完整关卡”可以从剪贴板读取关卡截图或单个上述 JSON 对象。剪贴板同时包含图片和文本时优先识别图片；直接按 `Ctrl+V` 粘贴 JSON 时始终按完整关卡导入。JSON 中的负数会直接恢复为隐藏数字，`0` 保留为非关卡格。“识别隐藏”和“识别初始阵型”仍只读取图片。

新建编辑器关卡默认使用算法5：最大交叉数量 `20`、拐弯概率 `40%`，前期、中期和后期隐藏概率均为 `50%`，三个阶段的邻近隐藏跳过概率均为 `0%`。

六边形蜂窝棋盘不产生交叉，所有算法都会将 `targetCrossings` 解析为 `0`。编辑器中统一按“最大交叉数量”解释，不会为了凑满该数值主动制造交叉。

算法2会从全部激活格中按生成种子随机选择起点，不再偏向边缘或内部；若棋盘拓扑本身存在两个强制端点，则仍从合法端点开始。大多数步骤按“拐弯概率”随机打乱候选方向，少量步骤使用低自由度安全引导，死局、断路或超过交叉上限时通过回溯改走其他方向。每次生成多条完整路径后随机选择一条；若随机搜索未在预算内完成，则使用稳定搜索作为后备。随后随机翻转仍能合法重连的路径片段，每次变换都重新验证相邻关系和交叉上限，用来打散局部区域的填充顺序。确定路径后按隐藏比例、最长连续隐藏和最长连续显示生成固定隐藏数字，不再搜索第二解或修复显示数字，因此同一组显示数字可以对应多条完整的一笔连解。

算法3复用算法2的完整路径生成，只替换隐藏候选的选取方式。每个非首尾数字会先分类为直线、拐弯或交叉；交叉指参与几何交叉的两条线段两端数字，并优先于另外两类。三类概率分别决定格子能否进入本次隐藏候选，隐藏占比限制总数量，隐藏成片最大尺寸限制空间上相邻的隐藏格连通块大小，与数字是否连续无关。方形、菱形和长方形按八邻域计算成片范围，六边形蜂窝按六邻域计算。概率、占比或成片尺寸无法同时满足时，实际隐藏数量可能低于目标值。算法3同样不搜索第二解、不强制唯一解。六边形蜂窝棋盘没有交叉，交叉相关参数在编辑器中禁用。

算法4复用算法2的完整路径生成，但拥有独立的隐藏选择逻辑。完整路径生成后，按步骤顺序划分为前 `25%`、中间 `50%`、后 `25%`，每个非首尾数字依次使用所属阶段的隐藏概率进行一次判断，不再使用隐藏比例或目标隐藏数量。若候选数字被选中且其空间邻格中已经存在隐藏数字，再使用所属阶段的“邻近隐藏跳过概率”进行第二次判断；实际跳过概率为配置概率乘以“当前周围已隐藏数字数量 ÷ 当前格实际有效邻居总数”。例如配置 `60`，中心格周围隐藏 `2/8` 时实际为 `15%`，边角格周围隐藏 `1/3` 时实际为 `20%`，周围全部隐藏时实际等于配置的 `60%`。命中时取消当前数字的隐藏并顺延到下一个。分母只统计棋盘内实际存在的有效邻格；方形、菱形和长方形按八邻域判断，六边形蜂窝按六邻域判断。最长连续隐藏始终限制新增隐藏；若继续显示会超过最长连续显示，当前数字会被强制隐藏，此时最长连续显示优先于邻近隐藏跳过概率。旧关卡中算法4的 `hiddenPercent` 只在读取时迁移为三个阶段相同的隐藏概率；本次调整前暂存的三个跳过开关也会分别迁移为 `0` 或 `100`，新保存的数据不再包含这些旧字段。

算法5沿用算法4的路径生成、前中后期隐藏概率和最长连续隐藏/显示限制，但将“周围一圈”隐藏判断改为同行同列判断。候选数字被隐藏概率选中后，实际跳过概率为本阶段配置概率乘以“同行或同列中已隐藏数字数量 ÷ 同行或同列中实际存在的其他数字总数”；同行同列中已隐藏数字越多，跳过当前隐藏的概率越高。算法5使用独立的 `algorithm-5` 标识和三项同行同列跳过概率参数。

## 算法4批量生成

关卡列表中的“批量生成”支持读取 `.xlsx` 配置表。配置表可以在最前面保留仅用于人工编号、生成时会忽略的 `id` 列；算法表头依次为：`棋盘形状`、`行数`、`列数`、`最大交叉数量`、`拐弯概率 %`、`前期隐藏概率 %`、`中期隐藏概率 %`、`后期隐藏概率 %`、`最长连续隐藏`、`最长连续显示`、`前期邻近隐藏跳过概率 %`、`中期邻近隐藏跳过概率 %`、`后期邻近隐藏跳过概率 %`、`生成次数`。每个非空配置行会生成“生成次数”指定的关卡，并追加到当前关卡列表；算法参数留空时使用算法4默认值。所有概率列统一填写 `0–100` 的整数并使用普通整数单元格格式，例如 `15` 表示 `15%`、`90` 表示 `90%`；不再使用 `0.15`、Excel 百分比单元格或“是/否”。

批量生成会填满配置指定的棋盘。正方形、菱形和六边形蜂窝的行列数必须相同；菱形最大 `8×8`，六边形蜂窝最大 `10×10`，其余尺寸范围为每边 `3–20`。单行最多生成 `100` 关，单次导入总计最多生成 `500` 关。

批量生成期间使用模态弹窗显示已处理数量和百分比。生成结束后，弹窗中的“下载本次 TXT”只对本次成功生成的关卡运行模拟并生成文件，不会混入列表中此前已有的关卡。

关卡列表使用 Tab 分隔的 `levels.txt` 导出，不包含表头且每关占一行。导出 ID 独立于编辑器关卡列表，每次导出都按照文件中的行顺序从 `1` 开始编号。前三列固定为导出 ID、单行紧凑关卡 JSON、棋盘形状，后续依次输出行数、列数、格子数、生成算法、路径与隐藏统计以及当前模拟次数和推理能力配置下的模拟汇总数据。难度汇总包含平均每步难度分，以及按步骤顺序约 25% / 50% / 25% 划分的前期、中期和后期平均难度分。

## 新增算法

1. 在 `types.ts` 定义独立参数接口和 selection，并加入 `EditorAlgorithmSelection` 联合类型。
2. 新建算法模块，实现默认参数和执行逻辑。
3. 在 `registry.ts` 注册名称、说明、兼容解析和运行分派。
4. 在 `parameterEditors.ts` 添加该算法专属的 DOM 参数面板。
5. 算法运行只接收 `EditorAlgorithmContext`，不要直接访问控制器、视图或 localStorage。

算法模块负责规则，参数编辑器负责 DOM，`LevelEditorModel` 只保存选择并调用注册表。
